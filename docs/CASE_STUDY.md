# 고객 문의를 분류하고 초안을 준비하는 자동화

지원팀은 문의를 읽고 종류를 나누고 답변 초안을 작성합니다. AI에게 고객 문장을 데이터로 제공하고 분류, 요약, 초안, 신뢰도를 정해진 JSON으로 받습니다. n8n은 결과 형식을 검사하고 고정된 업무 규칙을 적용합니다.

모델이 `refund` 또는 `account_access`로 표시한 문의는 사람에게 보냅니다. 주문 조회와 기술 문의만 신뢰도와 검토 여부 조건을 통과하면 로컬 CRM에 초안을 만듭니다. 발송 노드는 없습니다. 형식 검증은 잘못된 구조를 걸러내지만 잘못된 의미나 과도한 신뢰도를 알아낼 수는 없습니다.

문의 번호와 정규화된 내용은 SQLite에 저장합니다. 같은 요청을 동시에 보내도 한 번만 등록됩니다. 중복 응답에는 현재 상태와 기록 번호를 담아 완료와 미완료를 구별합니다. 중간에 멈춘 요청을 중복이라는 이유만으로 완료 처리하지 않습니다.

API가 시간 초과되어도 기록이 이미 저장됐을 수 있습니다. 그래서 응답을 확인할 수 없으면 실제 기록을 조회합니다. 기록이 없을 때만 쓰기 실패로 표시하고 재시도를 허용합니다. 조회 자체도 실패하면 결과 불명으로 반환합니다. 모든 상태·사업 기록 쓰기는 시도 번호를 확인하여 재시도 이전의 늦은 쓰기가 새 분류와 섞이지 않게 합니다.

CRM과 사람 검토 목록은 로컬 모의 시스템입니다. 실제 CRM에서는 idempotency key(같은 작업 식별자) 지원 또는 외부 기록 조회가 별도로 필요합니다. 로컬 SQLite의 한 트랜잭션으로 기록과 상태를 저장할 수 있다는 조건을 실제 SaaS에도 그대로 가정하면 안 됩니다.

재현 방법은 [실행 안내](RUN_LOCAL.md), 실행 결과와 남은 의존성 위험은 [검증 기록](VALIDATION.md)에 있습니다. 가짜 AI는 오류와 분류 결과를 강제로 만드는 테스트 도구이며 실제 모델의 정확도나 주입 공격 저항성을 평가하지 않습니다.
